# Boundary — Agent Arena

A cricket learning experiment with persistent players and an animated Babylon.js stadium. Watch a six-ball exhibition, create a player within a 100-coin budget, train its shot-selection policy, and replay saved challenges.

The [product requirements document](docs/REQUIREMENTS.md) defines the full game vision, proposed MVP scope, acceptance criteria and milestones.

The renderer runs on the viewer's device. FastAPI supplies the saved outcomes and ball trajectories; PostgreSQL stores the club, players, learning reports and matches. This makes Render + Supabase a practical temporary host without a rendering GPU server.

## Run

Requires Python 3.12+, uv, Node 22.12+ (tested with Node 24), and npm.

```sh
bash scripts/install.sh
bash scripts/start.sh
```

The server defaults to loopback port 8000. `HOST` and `PORT` override the listener. Local development uses `data/arena.sqlite3`; preserve this file to retain the club. `CRICKET_DB_PATH` selects another SQLite file. `DATABASE_URL` selects PostgreSQL instead. Environment files are not loaded automatically.

For frontend development, run `npm --prefix frontend run dev` alongside the backend. Vite proxies `/api` to port 8000.

## What the POC demonstrates

- Procedural 3D stadium, articulated cricketers, animated bowling, batting, ball flight, running, fielding and wickets; director, end-on and aerial cameras.
- Saved event replay with pause, speed, individual-ball selection, scoreboard, optional impact sound, fullscreen and actual browser performance measurements.
- Permanent player IDs, fixed initial power/timing/composure, transactional coin spending and globally unique normalized names among created players.
- A separate contextual-bandit policy and practice memory for each player. A training batch uses 2,000 deliveries, capped at 6,000 per player. Candidates replace deployed policies only after improvement on held-out simulated deliveries passes the confidence check.
- Persistence across server restarts, and exact saved matches even after the player's policy changes.

## Scope and limits

This is a **one-batter challenge**, not a complete cricket match. It ends after six balls, a wicket, or reaching the target. The non-striker is a visual actor; there is no strike rotation, eleven-player team selection, extras, independent bowling/fielding agents, transfers, earnings or league economy yet. The exhibition is a curated seeded replay, not a live stream or an evaluation sample.

The learning algorithm is a contextual bandit in a synthetic cricket model, not an LLM or a general self-modifying agent. Its evaluation includes a hand-authored heuristic baseline. Improving the initial policy does not establish an advantage over that baseline or real-world cricket accuracy.

The graphics are stylized procedural geometry. Photorealistic player assets, motion capture, a video broadcast pipeline, and measured 1080p60 performance on a real GPU are **not delivered**. Software-rendered Chromium in the cloud is slow; use the in-app Performance report to measure actual device performance. See [visual validation and next steps](docs/VALIDATION.md).

## Deploy and test

See [Render + Supabase setup](docs/DEPLOYMENT.md). The `render.yaml` Blueprint builds the Docker image and requires a persistent PostgreSQL URL. Hosted access uses a shared demo password; it is not multi-user account authorization.

```sh
.venv/bin/python -m pytest -q
npm --prefix frontend run build
# Install Playwright Chromium if system Chromium is not available:
cd frontend
npx playwright install chromium
npm run test:e2e
```

Browser tests use a temporary club and do not spend the development club's coins. Optional PostgreSQL integration tests require `CRICKET_TEST_POSTGRES_URL` pointing to a disposable localhost database server with permission to create databases and roles. They create and clean up uniquely named test databases. CI runs both database backends and the browser suite.

The scene and artwork are generated by this repository; no ESPN branding, commercial cricket models, or footage from another game is included. Babylon.js and other dependencies retain their respective licenses.
